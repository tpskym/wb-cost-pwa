# Мастерская · WB Cost PWA

Первая рабочая версия PWA для расчёта себестоимости 3D-печатных товаров и экономики продаж. Ручной ввод, локальная база, без сервера и npm-зависимостей.

## Запуск

```sh
npm start
```

Открыть `http://127.0.0.1:4173`. Нужны Python 3 и Node.js для тестов (`npm test`). Для использования приложения Node.js не требуется: это статические HTML/CSS/JS.

GitHub Pages: workflow `.github/workflows/pages.yml` проверяет формулы и публикует только файлы приложения. В Settings → Pages должен быть выбран источник GitHub Actions. Публичный интерфейс не содержит пользовательскую базу.

## Возможности v0.1

- Товары, копирование, ручные параметры производства и упаковки.
- Материалы, труд, электричество, оборудование, обслуживание, брак, коробки партии, этикетки, плёнка, карточки.
- Комиссия, реклама, эквайринг, логистика, невыкуп, хранение, приёмка и накладные.
- Произвольные расходы в рублях на изделие и процентах от цены.
- Себестоимость, прибыль, маржа, наценка, рентабельность, план за месяц, цена безубыточности и целевой маржи.
- Снимки расчётов, локальное сохранение, экспорт/полная загрузка JSON с резервной копией.
- PWA manifest и service worker для офлайн-работы после первого открытия. Установка зависит от браузера; рекомендуем проверить в Chrome/Edge на обеих ОС.

Пустые поля — неизвестные затраты. Числа при незаполненных полях являются частичными оценками. Для отсутствующего расхода нужно явно указать 0. Модель упаковки плановая, на выбранное количество изделий в общей коробке. Возврат предполагается годным для повторной продажи, потери задаются отдельно. Не делим всю себестоимость на долю выкупа.

НПД: 4% — покупатель-физлицо, 6% — организация/ИП ([ФНС](https://www.nalog.gov.ru/rn77/taxation/princtax/)). Плановый расчёт без применения временного налогового вычета. Полная выручка до удержаний является базой модели. Другие режимы пока представлены только ручной ставкой с выручки, это не полноценный расчёт УСН/НДС.

Потребление 200 Вт для PLA — редактируемая предварительная оценка. Официальную страницу [P2S](https://bambulab.com/en-us/p2s/specs) не удалось прочитать при подготовке; значение найдено в [копии спецификации производителя](https://manuals.plus/m/c7290dbe5b14377f7a95a546f92e44b04dc7aea597b42810d0955bd3aecd134a). Проверить по измерению, особенно при прогреве и сушке AMS. Тариф по умолчанию — 5 ₽/кВт·ч.

## Данные и Google Drive

Готовы скачивание и загрузка всей базы через JSON. В браузерах с File System Access можно вручную выбрать файл из локальной папки Google Drive. Перед записью проверяется, изменился ли файл после выбора, но атомарной блокировки между компьютерами нет: не записывать одновременно. После записи дождаться синхронизации настольного Google Drive.

Подготовлен Google OAuth (`drive.file`, токен только в памяти), создание видимых файлов-снимков и полная загрузка. Для включения нужен ваш OAuth Client ID, Google Drive API, разрешённый origin приложения и настройка consent screen в Google Cloud. Этот путь пока не проверен с реальным аккаунтом. Автоматическая перезапись единственного общего файла отключена; согласованная автоматическая синхронизация с защитой конфликтов ещё не завершена. Параметры OAuth вводятся в «Данные и синхронизация» и хранятся только локально.

Браузерная база зависит от профиля и адреса приложения: localhost и GitHub Pages имеют разные хранилища. Перенос — экспорт/импорт. Удаление данных браузера удаляет локальную базу, поэтому скачивайте копии. Фактические цены и пользовательские файлы не размещаются в репозитории.

## Ограничения первой версии

Окупаемость оборудования, полноценные сценарии нескольких площадок на одном товаре, закупочные партии, точное фактическое заполнение дневных коробок, автоматическая синхронизация, другие налоговые режимы и API маркетплейсов — следующие этапы. Выбор площадки пока является названием сценария, все тарифы вводятся вручную.

Подробный согласованный план: [требования](docs/requirements.md).


### Полная резервная копия (v0.2.17)

Кнопка «Полный экспорт ZIP» сохраняет JSON базы и все двоичные файлы всех товаров из IndexedDB, включая модели и исходники WB/Ozon. PDF-этикетки включены в базу. Восстановление: «Данные и синхронизация → Восстановить из ZIP». Формат архива — ZIP без сжатия, с manifest.json, database.json и каталогом files/. Обычный JSON-экспорт остаётся доступен отдельно и не содержит файлов IndexedDB.

Перед восстановлением проверяются состав архива, CRC каждого файла, схема базы и привязки к товарам. Все файлы записываются одной транзакцией в новом пространстве базы; текущая база переключается только после успешной записи файлов. Предыдущие данные и файлы сохраняются для команды «Вернуть предыдущую базу».

### Прямое подключение WB / Ozon (v0.2.19)

Раздел «Карточки WB и Ozon · API» работает из PWA через CORS, без внешнего сервера. Ключ WB категории «Контент» и Ozon Client-Id / API-Key вводятся в интерфейсе. По умолчанию ключи находятся в памяти вкладки, сохранение в localStorage отдельно включается флажком. Ключи никогда не добавляются в db, JSON, полный ZIP, шаблоны или IndexedDB файлов. Кнопка удаления ключей очищает память и выделенный ключ localStorage.

Поддерживаются проверка чтения, список с пагинацией, черновик новой карточки, загрузка существующей, редактирование, отправка одного товара и проверка ответа обработки. Для WB есть отдельная замена фотографий по HTTPS-ссылкам. Для Ozon ссылки задаются в images. Локальные исходники не становятся публичными URL автоматически. Создание и изменение требуют подтверждения в UI; ошибки сети не вызывают автоматическую повторную отправку.

В редакторе v0.2.21 JSON не требуется: название, артикул, бренд WB, цена и НДС Ozon, габариты, масса, штрихкоды и размеры вводятся обычными полями. Категории находятся по названию, характеристики загружаются для выбранного предмета/типа; для справочников Ozon есть поиск и пагинация, для составных характеристик — группы полей. Старые черновики продолжают работать без изменения формата базы, исходные идентификаторы и поля вне редактируемых характеристик сохраняются.

Фотографии выбираются из исходников выбранной площадки (JPG/PNG/WebP), показываются превью, поддерживается изменение порядка и исключение из карточки без удаления исходника. Для Ozon продавец указывает прямые HTTPS-ссылки на свои файлы; локальные blob-URL не отправляются в Seller API. Для WB доступна прямая multipart-загрузка выбранных файлов после создания карточки: найти созданную карточку → загрузить выбранные файлы → обновить фото → применить состав/порядок. Загрузка и изменение состава требуют отдельного подтверждения. При загрузке файлы добавляются после актуального числа фотографий с площадки, а неопределённый результат сети не повторяется автоматически.

Для автоматических тестов используются jsdom и fake-indexeddb (только devDependencies); production остаётся статической PWA без сервера и сторонних runtime-библиотек.

Официальные спецификации: https://dev.wildberries.ru/docs/openapi/work-with-products и https://docs.ozon.ru/api/seller/ . Авторизованные запросы и доступность конкретных категорий требуют проверки ключами продавца; без ключей проверены CORS-preflight и автоматические тесты с подставленными ответами API.

### Локальный справочник категорий (v0.2.23)

Во вкладке «Настройки API» кнопка скачивания категорий загружает полный справочник для выбранной площадки: у WB проходятся все страницы с offset, у Ozon сохраняется дерево в виде списка типов с полными путями категорий. Справочники хранятся в отдельной IndexedDB workshop-category-catalogs-v1 и доступны всем товарам и после перезагрузки. Поиск по нескольким словам работает локально, без ключей и запросов к API, учитывает названия родителей и подкатегорий и не различает е/ё. Все найденные элементы доступны через «Показать ещё 200 категорий». Обновление заменяет копию только после завершения загрузки; дата и количество записей видны рядом с выбором. Характеристики загружаются по API отдельно при выборе категории. Справочник является возобновляемым локальным кэшем, а не частью базы расчётов.


### Справка по полям (v0.2.24)

У каждой характеристики есть «Справка по заполнению»: описание, обязательность, тип, единицы, множественность, максимальное количество значений и другие доступные признаки из API. Когда описание не передано, это указано явно. Условия применения не придумываются: выводятся в составе полученного описания. Примечания к выбранным справочным значениям Ozon показываются отдельно и не отправляются как значения характеристик. Подсказки для основных полей помечены как подсказки приложения. Для обновления метаданных ранее загруженной категории нажмите «Загрузить характеристики категории».


### Вкладки API (v0.2.25)

В разделе карточек сверху две вкладки: «Карточки» и «Настройки API». В настройках находятся ключи WB/Ozon, сохранение ключей на устройстве, отдельные проверки доступа и скачивание полных справочников каждой площадки. В карточке остаются выбор категории из локального справочника и загрузка её характеристик. Переключение вкладок не пересоздаёт поля редактора, а справочник в нём перечитывается после обновления в настройках.


В версии v0.2.26 рядом с поиском добавлена кнопка «Загрузить все мои карточки». Она не использует поле поиска, проходит все страницы API выбранной площадки, показывает общее количество и не меняет товары на площадке. При повторяющейся странице загрузка прерывается с сообщением, а прежний список остаётся доступным.

### 0.2.42
В списках карточек добавлены остатки и проверка ошибок создания. WB: остатки FBS по всем складам продавца (токен «Маркетплейс»), полный список ошибок создания показывается отдельно, включая отсутствующие в списке карточки. Ozon: остатки и резерв, контент-рейтинг 0–100 по SKU (дополнительные роли Stocks и Rating). Ошибки запросов не считаются отсутствием ошибок товара. Оценка качества WB не запрашивается: подтверждённого публичного метода нет; интерфейс явно сообщает ограничение. Кнопки редактирования и обновления компактные, с подсказками. Подтверждения в редакторе заменены на диалог приложения.

Поля со справочниками показывают выбранное значение, кнопки списка и поиска открывают отдельный диалог. При открытии списка варианты загружаются автоматически; поиск по фильтру запускается кнопкой или Enter. Выбор применяется отдельной кнопкой; отмена сохраняет прежнее значение.

### Получение ключей и права
Инструкция также доступна во вкладке «Настройки API» приложения.

- WB Partners → настройки → «Интеграции по API» → персональный токен для ручной интеграции. Категории «Контент» (карточки, фото, ошибки) и «Маркетплейс» (остатки FBS и склады продавца). Для изменения карточек отключите режим «Только чтение».
- Ozon Seller → настройки → Seller API. Роли Product (полная, для чтения/изменения карточек), Description Category (категории/типы/характеристики/справочники), Stocks (остатки/резерв), Rating (контент-рейтинг). Admin не нужен. Укажите Client-Id и API-Key, затем «Применить ключи». При выдаче нового ключа замените его в приложении.

### 0.2.56 — промпт для описания
Рядом с описанием WB и характеристиками «Описание»/«Аннотация» добавлена кнопка «Промпт для ИИ». Окно собирает сведения из текущего черновика, включая характеристики и сложные группы; объём текста можно изменить. Копирование через clipboard с резервным выделением текста. Промпт требует естественно использовать релевантные ключевые слова, сохранять факты и комплектацию, не смешивать размеры товара и упаковки. Лимиты берутся из метаданных поля при наличии; для WB используется ориентир по категориям из инструкции, для Ozon без метаданных предлагается редактируемый объём 2000 символов, явно не официальный лимит. Тексты и характеристики не отправляются автоматически ни в ИИ, ни на площадку.

### 0.2.57 — отдельные значения и баркоды
Текстовые коллекции характеристик вводятся по одному значению с добавлением и удалением, с учётом максимального количества. API по-прежнему получает массив значений, не строку с произвольным разделителем.

WB: кнопка генерации получает один код через POST /content/v2/barcodes и добавляет в выбранный размер, не перезаписывая вручную введённые штрихкоды. Отправка карточки остаётся отдельным действием.

Ozon: генерация POST /v1/barcode/generate требует роль Barcode и существующий product_id, предварительно проверяет баркоды через info/list. Перед генерацией на площадке — подтверждение. После запроса считывается баркод; если ещё не готов, отдельная кнопка «Получить баркод из Ozon» без повторной генерации. При неизвестном результате генерация заблокирована до получения кода. Ручной ввод сохранён. Проверка ролей и инструкция теперь включают Product, Description Category, Stocks, Rating, Barcode.

### 0.2.62 — цены WB
Для токена WB дополнительно нужен доступ «Цены и скидки» с правом записи для изменения цены. Эта категория добавлена в инструкцию и подпись поля ключа. GET /api/v2/list/goods/filter (filterNmID) и POST /api/v2/upload/task отправляются на discounts-prices-api.wildberries.ru. Цена WB до скидки загружается отдельной кнопкой; рядом — себестоимость по артикулу из локальной базы и калькулятор WB. Изменение цены отдельно от содержимого карточки, с подтверждением и сохранением скидки продавца. Перед отправкой проверяются актуальные цена/скидка; при изменении на площадке требуется перечитать их. Разные цены по размерам отображаются, но не перезаписываются общей ценой. Принятие задачи не означает применения цены, для проверки требуется перечитать её или открыть кабинет.

### 0.2.63 — поиск и автоматическая себестоимость
Поле поиска карточек изначально пустое, очищается после загрузки и при открытии карточки. Пагинация сохраняет введённый фильтр отдельно от очищенного поля. При открытии черновика WB/Ozon автоматически ищется себестоимость по артикулу открытой карточки; «Обновить себестоимость» повторяет поиск. Результат содержит переход к локальному товару; при известной HTTPS-ссылке — также переход к товару на площадке. Для открытых карточек сохраняется ссылка по nmID WB или известному SKU Ozon (не по product_id).

### 0.2.64 — подробные цены и скидки
WB: редактируемые цена до скидки, процент продавца и цена после скидки; вычисления связаны. Скидка WB требует целого процента. Цены и скидки отправляются отдельно с подтверждением, перед отправкой проверяется актуальность исходного состояния. Размерные цены не перезаписываются общей ценой.

Ozon: подробные данные из POST /v5/product/info/prices. Редактируются зачёркнутая/обычная цены, производный процент и минимальная цена; изменение обычной цены и old_price также сохраняется в черновике карточки. Для существующего товара отдельная отправка через POST /v1/product/import/prices, результат проверяется по updated/errors. Требуется Product. Цена marketing_seller_price и её относительная скидка показаны справочно; условия акций не изменяются. Скидки Ozon/банка и конечная покупательская цена не моделируются. Для новой карточки минимальная цена устанавливается отдельным запросом после создания. Автозагрузка подробных цен при открытии карточки не блокирует загрузку характеристик при отсутствии доступа к ценам.

### 0.2.65 — обратный переход и основная цена
В расчёте себестоимости для WB и Ozon добавлены кнопки открытия сохранённого редактора карточки по точному артикулу. Поиск идёт по черновикам всех товаров базы; при нескольких совпадениях открывается последний загруженный. При отсутствии карточки кнопка неактивна с пояснением. В ценовом редакторе основная цена продажи стоит первой, рядом скидка и начальная/зачёркнутая цена; Ozon всегда показывает поле old_price.

### 0.2.66 — компактный блок цены и переход между площадками
Цена, скидка и начальная/зачёркнутая цена расположены в одной строке без вложенного блока себестоимости. Под ними отдельная панель с артикулом, себестоимостью, ссылками и кнопкой перехода к карточке другой площадки по тому же артикулу. Сохранённый редактор открывается без перезаписи; если карточка ещё не загружена, выполняется поиск на другой площадке и открывается точное совпадение. Замена другого локального черновика требует подтверждения.
