# Мастерская · WB Cost PWA

Первая рабочая версия PWA для расчёта себестоимости 3D-печатных товаров и экономики продаж. Ручной ввод, локальная база, без сервера и npm-зависимостей.

## Запуск

```sh
npm start
```

Открыть `http://127.0.0.1:4173`. Нужны Python 3 и Node.js для тестов (`npm test`). Для использования приложения Node.js не требуется: это статические HTML/CSS/JS.

GitHub Pages: workflow `.github/workflows/pages.yml` проверяет формулы и публикует только файлы приложения. В Settings → Pages должен быть выбран источник GitHub Actions. Публичный интерфейс не содержит пользовательскую базу.

## Возможности v0.1

- Товары, копирование, ручные параметры производства и упаковки.
- Материалы, труд, электричество, оборудование, обслуживание, брак, коробки партии, этикетки, плёнка, карточки.
- Комиссия, реклама, эквайринг, логистика, невыкуп, хранение, приёмка и накладные.
- Произвольные расходы в рублях на изделие и процентах от цены.
- Себестоимость, прибыль, маржа, наценка, рентабельность, план за месяц, цена безубыточности и целевой маржи.
- Снимки расчётов, локальное сохранение, экспорт/полная загрузка JSON с резервной копией.
- PWA manifest и service worker для офлайн-работы после первого открытия. Установка зависит от браузера; рекомендуем проверить в Chrome/Edge на обеих ОС.

Пустые поля — неизвестные затраты. Числа при незаполненных полях являются частичными оценками. Для отсутствующего расхода нужно явно указать 0. Модель упаковки плановая, на выбранное количество изделий в общей коробке. Возврат предполагается годным для повторной продажи, потери задаются отдельно. Не делим всю себестоимость на долю выкупа.

НПД: 4% — покупатель-физлицо, 6% — организация/ИП ([ФНС](https://www.nalog.gov.ru/rn77/taxation/princtax/)). Плановый расчёт без применения временного налогового вычета. Полная выручка до удержаний является базой модели. Другие режимы пока представлены только ручной ставкой с выручки, это не полноценный расчёт УСН/НДС.

Потребление 200 Вт для PLA — редактируемая предварительная оценка. Официальную страницу [P2S](https://bambulab.com/en-us/p2s/specs) не удалось прочитать при подготовке; значение найдено в [копии спецификации производителя](https://manuals.plus/m/c7290dbe5b14377f7a95a546f92e44b04dc7aea597b42810d0955bd3aecd134a). Проверить по измерению, особенно при прогреве и сушке AMS. Тариф по умолчанию — 5 ₽/кВт·ч.

## Данные и Google Drive

Готовы скачивание и загрузка всей базы через JSON. В браузерах с File System Access можно вручную выбрать файл из локальной папки Google Drive. Перед записью проверяется, изменился ли файл после выбора, но атомарной блокировки между компьютерами нет: не записывать одновременно. После записи дождаться синхронизации настольного Google Drive.

Подготовлен Google OAuth (`drive.file`, токен только в памяти), создание видимых файлов-снимков и полная загрузка. Для включения нужен ваш OAuth Client ID, Google Drive API, разрешённый origin приложения и настройка consent screen в Google Cloud. Этот путь пока не проверен с реальным аккаунтом. Автоматическая перезапись единственного общего файла отключена; согласованная автоматическая синхронизация с защитой конфликтов ещё не завершена. Параметры OAuth вводятся в «Данные и синхронизация» и хранятся только локально.

Браузерная база зависит от профиля и адреса приложения: localhost и GitHub Pages имеют разные хранилища. Перенос — экспорт/импорт. Удаление данных браузера удаляет локальную базу, поэтому скачивайте копии. Фактические цены и пользовательские файлы не размещаются в репозитории.

## Ограничения первой версии

Окупаемость оборудования, полноценные сценарии нескольких площадок на одном товаре, закупочные партии, точное фактическое заполнение дневных коробок, автоматическая синхронизация, другие налоговые режимы и API маркетплейсов — следующие этапы. Выбор площадки пока является названием сценария, все тарифы вводятся вручную.

Подробный согласованный план: [требования](docs/requirements.md).
