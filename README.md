# Мастерская · WB Cost PWA

Первая рабочая версия PWA для расчёта себестоимости 3D-печатных товаров и экономики продаж. Ручной ввод, локальная база, без сервера и npm-зависимостей.

## Запуск

```sh
npm start
```

Открыть `http://127.0.0.1:4173`. Нужны Python 3 и Node.js для тестов (`npm test`). Для использования приложения Node.js не требуется: это статические HTML/CSS/JS.

GitHub Pages: workflow `.github/workflows/pages.yml` проверяет формулы и публикует только файлы приложения. В Settings → Pages должен быть выбран источник GitHub Actions. Публичный интерфейс не содержит пользовательскую базу.

## Возможности v0.1

- Товары, копирование, ручные параметры производства и упаковки.
- Материалы, труд, электричество, оборудование, обслуживание, брак, коробки партии, этикетки, плёнка, карточки.
- Комиссия, реклама, эквайринг, логистика, невыкуп, хранение, приёмка и накладные.
- Произвольные расходы в рублях на изделие и процентах от цены.
- Себестоимость, прибыль, маржа, наценка, рентабельность, план за месяц, цена безубыточности и целевой маржи.
- Снимки расчётов, локальное сохранение, экспорт/полная загрузка JSON с резервной копией.
- PWA manifest и service worker для офлайн-работы после первого открытия. Установка зависит от браузера; рекомендуем проверить в Chrome/Edge на обеих ОС.

Пустые поля — неизвестные затраты. Числа при незаполненных полях являются частичными оценками. Для отсутствующего расхода нужно явно указать 0. Модель упаковки плановая, на выбранное количество изделий в общей коробке. Возврат предполагается годным для повторной продажи, потери задаются отдельно. Не делим всю себестоимость на долю выкупа.

НПД: 4% — покупатель-физлицо, 6% — организация/ИП ([ФНС](https://www.nalog.gov.ru/rn77/taxation/princtax/)). Плановый расчёт без применения временного налогового вычета. Полная выручка до удержаний является базой модели. Другие режимы пока представлены только ручной ставкой с выручки, это не полноценный расчёт УСН/НДС.

Потребление 200 Вт для PLA — редактируемая предварительная оценка. Официальную страницу [P2S](https://bambulab.com/en-us/p2s/specs) не удалось прочитать при подготовке; значение найдено в [копии спецификации производителя](https://manuals.plus/m/c7290dbe5b14377f7a95a546f92e44b04dc7aea597b42810d0955bd3aecd134a). Проверить по измерению, особенно при прогреве и сушке AMS. Тариф по умолчанию — 5 ₽/кВт·ч.

## Данные и Google Drive

Готовы скачивание и загрузка всей базы через JSON. В браузерах с File System Access можно вручную выбрать файл из локальной папки Google Drive. Перед записью проверяется, изменился ли файл после выбора, но атомарной блокировки между компьютерами нет: не записывать одновременно. После записи дождаться синхронизации настольного Google Drive.

Подготовлен Google OAuth (`drive.file`, токен только в памяти), создание видимых файлов-снимков и полная загрузка. Для включения нужен ваш OAuth Client ID, Google Drive API, разрешённый origin приложения и настройка consent screen в Google Cloud. Этот путь пока не проверен с реальным аккаунтом. Автоматическая перезапись единственного общего файла отключена; согласованная автоматическая синхронизация с защитой конфликтов ещё не завершена. Параметры OAuth вводятся в «Данные и синхронизация» и хранятся только локально.

Браузерная база зависит от профиля и адреса приложения: localhost и GitHub Pages имеют разные хранилища. Перенос — экспорт/импорт. Удаление данных браузера удаляет локальную базу, поэтому скачивайте копии. Фактические цены и пользовательские файлы не размещаются в репозитории.

## Ограничения первой версии

Окупаемость оборудования, полноценные сценарии нескольких площадок на одном товаре, закупочные партии, точное фактическое заполнение дневных коробок, автоматическая синхронизация, другие налоговые режимы и API маркетплейсов — следующие этапы. Выбор площадки пока является названием сценария, все тарифы вводятся вручную.

Подробный согласованный план: [требования](docs/requirements.md).


### Полная резервная копия (v0.2.17)

Кнопка «Полный экспорт ZIP» сохраняет JSON базы и все двоичные файлы всех товаров из IndexedDB, включая модели и исходники WB/Ozon. PDF-этикетки включены в базу. Восстановление: «Данные и синхронизация → Восстановить из ZIP». Формат архива — ZIP без сжатия, с manifest.json, database.json и каталогом files/. Обычный JSON-экспорт остаётся доступен отдельно и не содержит файлов IndexedDB.

Перед восстановлением проверяются состав архива, CRC каждого файла, схема базы и привязки к товарам. Все файлы записываются одной транзакцией в новом пространстве базы; текущая база переключается только после успешной записи файлов. Предыдущие данные и файлы сохраняются для команды «Вернуть предыдущую базу».

### Прямое подключение WB / Ozon (v0.2.19)

Раздел «Карточки WB и Ozon · API» работает из PWA через CORS, без внешнего сервера. Ключ WB категории «Контент» и Ozon Client-Id / API-Key вводятся в интерфейсе. По умолчанию ключи находятся в памяти вкладки, сохранение в localStorage отдельно включается флажком. Ключи никогда не добавляются в db, JSON, полный ZIP, шаблоны или IndexedDB файлов. Кнопка удаления ключей очищает память и выделенный ключ localStorage.

Поддерживаются проверка чтения, список с пагинацией, черновик новой карточки, загрузка существующей, редактирование, отправка одного товара и проверка ответа обработки. Для WB есть отдельная замена фотографий по HTTPS-ссылкам. Для Ozon ссылки задаются в images. Локальные исходники не становятся публичными URL автоматически. Создание и изменение требуют подтверждения в UI; ошибки сети не вызывают автоматическую повторную отправку.

В редакторе v0.2.21 JSON не требуется: название, артикул, бренд WB, цена и НДС Ozon, габариты, масса, штрихкоды и размеры вводятся обычными полями. Категории находятся по названию, характеристики загружаются для выбранного предмета/типа; для справочников Ozon есть поиск и пагинация, для составных характеристик — группы полей. Старые черновики продолжают работать без изменения формата базы, исходные идентификаторы и поля вне редактируемых характеристик сохраняются.

Фотографии выбираются из исходников выбранной площадки (JPG/PNG/WebP), показываются превью, поддерживается изменение порядка и исключение из карточки без удаления исходника. Для Ozon продавец указывает прямые HTTPS-ссылки на свои файлы; локальные blob-URL не отправляются в Seller API. Для WB доступна прямая multipart-загрузка выбранных файлов после создания карточки: найти созданную карточку → загрузить выбранные файлы → обновить фото → применить состав/порядок. Загрузка и изменение состава требуют отдельного подтверждения. При загрузке файлы добавляются после актуального числа фотографий с площадки, а неопределённый результат сети не повторяется автоматически.

Для автоматических тестов используются jsdom и fake-indexeddb (только devDependencies); production остаётся статической PWA без сервера и сторонних runtime-библиотек.

Официальные спецификации: https://dev.wildberries.ru/docs/openapi/work-with-products и https://docs.ozon.ru/api/seller/ . Авторизованные запросы и доступность конкретных категорий требуют проверки ключами продавца; без ключей проверены CORS-preflight и автоматические тесты с подставленными ответами API.

### Локальный справочник категорий (v0.2.23)

Во вкладке «Настройки API» кнопка скачивания категорий загружает полный справочник для выбранной площадки: у WB проходятся все страницы с offset, у Ozon сохраняется дерево в виде списка типов с полными путями категорий. Справочники хранятся в отдельной IndexedDB workshop-category-catalogs-v1 и доступны всем товарам и после перезагрузки. Поиск по нескольким словам работает локально, без ключей и запросов к API, учитывает названия родителей и подкатегорий и не различает е/ё. Все найденные элементы доступны через «Показать ещё 200 категорий». Обновление заменяет копию только после завершения загрузки; дата и количество записей видны рядом с выбором. Характеристики загружаются по API отдельно при выборе категории. Справочник является возобновляемым локальным кэшем, а не частью базы расчётов.


### Справка по полям (v0.2.24)

У каждой характеристики есть «Справка по заполнению»: описание, обязательность, тип, единицы, множественность, максимальное количество значений и другие доступные признаки из API. Когда описание не передано, это указано явно. Условия применения не придумываются: выводятся в составе полученного описания. Примечания к выбранным справочным значениям Ozon показываются отдельно и не отправляются как значения характеристик. Подсказки для основных полей помечены как подсказки приложения. Для обновления метаданных ранее загруженной категории нажмите «Загрузить характеристики категории».


### Вкладки API (v0.2.25)

В разделе карточек сверху две вкладки: «Карточки» и «Настройки API». В настройках находятся ключи WB/Ozon, сохранение ключей на устройстве, отдельные проверки доступа и скачивание полных справочников каждой площадки. В карточке остаются выбор категории из локального справочника и загрузка её характеристик. Переключение вкладок не пересоздаёт поля редактора, а справочник в нём перечитывается после обновления в настройках.


В версии v0.2.26 рядом с поиском добавлена кнопка «Загрузить все мои карточки». Она не использует поле поиска, проходит все страницы API выбранной площадки, показывает общее количество и не меняет товары на площадке. При повторяющейся странице загрузка прерывается с сообщением, а прежний список остаётся доступным.

### Получение ключей и права
Инструкция также доступна во вкладке «Настройки API» приложения.

- WB Partners → настройки → «Интеграции по API» → персональный токен для ручной интеграции. Категории «Контент» (карточки, фото, ошибки) и «Маркетплейс» (остатки FBS и склады продавца). Для изменения карточек отключите режим «Только чтение».
- Ozon Seller → настройки → Seller API. Роли Product (полная, для чтения/изменения карточек), Description Category (категории/типы/характеристики/справочники), Stocks (остатки/резерв), Rating (контент-рейтинг). Admin не нужен. Укажите Client-Id и API-Key, затем «Применить ключи». При выдаче нового ключа замените его в приложении.

### 0.2.56 — промпт для описания
Рядом с описанием WB и характеристиками «Описание»/«Аннотация» добавлена кнопка «Промпт для ИИ». Окно собирает сведения из текущего черновика, включая характеристики и сложные группы; объём текста можно изменить. Копирование через clipboard с резервным выделением текста. Промпт требует естественно использовать релевантные ключевые слова, сохранять факты и комплектацию, не смешивать размеры товара и упаковки. Лимиты берутся из метаданных поля при наличии; для WB используется ориентир по категориям из инструкции, для Ozon без метаданных предлагается редактируемый объём 2000 символов, явно не официальный лимит. Тексты и характеристики не отправляются автоматически ни в ИИ, ни на площадку.

### 0.2.57 — отдельные значения и баркоды
Текстовые коллекции характеристик вводятся по одному значению с добавлением и удалением, с учётом максимального количества. API по-прежнему получает массив значений, не строку с произвольным разделителем.

WB: кнопка генерации получает один код через POST /content/v2/barcodes и добавляет в выбранный размер, не перезаписывая вручную введённые штрихкоды. Отправка карточки остаётся отдельным действием.

Ozon: генерация POST /v1/barcode/generate требует роль Barcode и существующий product_id, предварительно проверяет баркоды через info/list. Перед генерацией на площадке — подтверждение. После запроса считывается баркод; если ещё не готов, отдельная кнопка «Получить баркод из Ozon» без повторной генерации. При неизвестном результате генерация заблокирована до получения кода. Ручной ввод сохранён. Проверка ролей и инструкция теперь включают Product, Description Category, Stocks, Rating, Barcode.

### 0.2.62 — цены WB
Для токена WB дополнительно нужен доступ «Цены и скидки» с правом записи для изменения цены. Эта категория добавлена в инструкцию и подпись поля ключа. GET /api/v2/list/goods/filter (filterNmID) и POST /api/v2/upload/task отправляются на discounts-prices-api.wildberries.ru. Цена WB до скидки загружается отдельной кнопкой; рядом — себестоимость по артикулу из локальной базы и калькулятор WB. Изменение цены отдельно от содержимого карточки, с подтверждением и сохранением скидки продавца. Перед отправкой проверяются актуальные цена/скидка; при изменении на площадке требуется перечитать их. Разные цены по размерам отображаются, но не перезаписываются общей ценой. Принятие задачи не означает применения цены, для проверки требуется перечитать её или открыть кабинет.

### 0.2.63 — поиск и автоматическая себестоимость
Поле поиска карточек изначально пустое, очищается после загрузки и при открытии карточки. Пагинация сохраняет введённый фильтр отдельно от очищенного поля. При открытии черновика WB/Ozon автоматически ищется себестоимость по артикулу открытой карточки; «Обновить себестоимость» повторяет поиск. Результат содержит переход к локальному товару; при известной HTTPS-ссылке — также переход к товару на площадке. Для открытых карточек сохраняется ссылка по nmID WB или известному SKU Ozon (не по product_id).

### 0.2.64 — подробные цены и скидки
WB: редактируемые цена до скидки, процент продавца и цена после скидки; вычисления связаны. Скидка WB требует целого процента. Цены и скидки отправляются отдельно с подтверждением, перед отправкой проверяется актуальность исходного состояния. Размерные цены не перезаписываются общей ценой.

Ozon: подробные данные из POST /v5/product/info/prices. Редактируются зачёркнутая/обычная цены, производный процент и минимальная цена; изменение обычной цены и old_price также сохраняется в черновике карточки. Для существующего товара отдельная отправка через POST /v1/product/import/prices, результат проверяется по updated/errors. Требуется Product. Цена marketing_seller_price и её относительная скидка показаны справочно; условия акций не изменяются. Скидки Ozon/банка и конечная покупательская цена не моделируются. Для новой карточки минимальная цена устанавливается отдельным запросом после создания. Автозагрузка подробных цен при открытии карточки не блокирует загрузку характеристик при отсутствии доступа к ценам.

### 0.2.65 — обратный переход и основная цена
В расчёте себестоимости для WB и Ozon добавлены кнопки открытия сохранённого редактора карточки по точному артикулу. Поиск идёт по черновикам всех товаров базы; при нескольких совпадениях открывается последний загруженный. При отсутствии карточки кнопка неактивна с пояснением. В ценовом редакторе основная цена продажи стоит первой, рядом скидка и начальная/зачёркнутая цена; Ozon всегда показывает поле old_price.

### 0.2.66 — компактный блок цены и переход между площадками
Цена, скидка и начальная/зачёркнутая цена расположены в одной строке без вложенного блока себестоимости. Под ними отдельная панель с артикулом, себестоимостью, ссылками и кнопкой перехода к карточке другой площадки по тому же артикулу. Сохранённый редактор открывается без перезаписи; если карточка ещё не загружена, выполняется поиск на другой площадке и открывается точное совпадение. Замена другого локального черновика требует подтверждения.

Материалы опубликованной карточки: кнопки «Показать прямые ссылки на материалы» и скачивания ZIP получают рич-контент WB из публичных данных карточки на CDN, используя адрес фотографий из API. Изображения и обложка сохраняются в `rich-content/`; статус загрузки отображается под ссылками и в `Материалы.json`. Для Ozon изображения извлекаются из доступного JSON рич-контента. Ручное добавление ссылок остаётся доступным. Если публичные данные WB недоступны, обычные фото продолжают загружаться.

В результатах загрузки материалов доступен просмотр и копирование текстов рич-контента с заголовками. В ZIP они сохраняются в `rich-content/Тексты с заголовками.txt` в порядке блоков; исходный доступный JSON — в `rich-content/Исходные данные.json`. Поддерживаются WB и JSON рич-контента Ozon, в том числе блоки без изображений.

Для полного набора фото Ozon при скачивании материалов дополнительно вызывается `POST /v2/product/pictures/info` по ID загруженного товара. Главное фото из `primary_photo` сохраняется первым; дубли дополнительных фотографий исключаются. При ошибке запроса доступные фото сохраняются, а неполная проверка отмечается в интерфейсе и `Материалы.json`.

Тексты Ozon: поддерживаются `TextWithContent` и `TextWithItems` из [официальной схемы](https://rich-content.ozon.ru/docs/modules/v0_3_text_types.html), включая inline-текст, ссылки и явные переносы строк. При наличии обоих представлений используется `items`, без дублирования. Если JSON или текст не получен, текстовый файл архива содержит пояснение.


### Заказы и продажи с площадок · только чтение

Раздел «Продажи» → «Заказы и продажи с площадок»: WB FBS / FBW и Ozon FBS / FBO, период за последние 90 дней, загрузка по кнопке, поиск по артикулу/товару/заказу, фильтр статуса и страницы по 50 позиций. Используются ключи из раздела карточек; «Ключи API» открывает настройки. Снимок каждой схемы заменяется только после успешного чтения всех страниц. Ошибки не удаляют старые данные; дата и период каждого снимка видны на экране. Снимки входят в JSON и полный ZIP вместе с остальной базой. Заказы не создают записи в ручном журнале продаж.

Используемые методы и права:

- WB FBS: `GET /api/v3/orders` (период разбивается на отрезки до 29 дней), `POST /api/v3/orders/status` — токен «Маркетплейс», достаточно чтения. [Документация WB FBS](https://dev.wildberries.ru/openapi/orders-fbs).
- WB FBW: `GET /api/v1/supplier/orders` и `GET /api/v1/supplier/sales`, хост `statistics-api.wildberries.ru` — токен «Статистика». Данные предварительные, обновление примерно раз в 30 минут; чтение одного отчёта ограничено минимум минутой, базовые токены имеют более строгие лимиты. Склад продавца исключается из отчёта, чтобы не дублировать FBS. [Отчёты WB](https://dev.wildberries.ru/openapi/reports).
- Ozon FBS: `POST /v4/posting/fbs/list`, роль `Posting FBS read-only` (или роль Posting FBS с доступом к чтению). [Документация](https://docs.ozon.ru/api/seller/#operation/PostingFbsList).
- Ozon FBO: `POST /v3/posting/fbo/list`, роль `Posting FBO`. [Документация](https://docs.ozon.ru/api/seller/#operation/PostingFboList).

Оба метода Ozon используют `cursor` и `has_next`, размер страницы 100. Цены читаются из объекта `price.amount` / `price.currency`. Неизвестные статусы не преобразуются в успешные. Для Ozon дата начала обработки подписана отдельно, если дата создания отсутствует. Признак «выкуп маркетплейсом» показывается отдельно от получения покупателем. WB FBW не предоставляет в этих отчётах все этапы доставки: без продажи/возврата/отмены отображается «Заказан · этап доставки API не сообщает». У заказов из отчёта продаж без соответствующего заказа дата заказа остаётся пустой, дата события показана отдельно. Ни статусы, ни предварительные расчётные начисления не используются как подтверждение реальной выплаты.

В модуле заказов закрытый список только читающих методов; отправка, отмена и смена статусов отсутствуют. Данные покупателей (имена, телефоны, адреса) не сохраняются в снимках. Автоматических фоновых запросов и повторов после ошибки нет. На большом отчёте WB от 80 000 строк загрузка останавливается с просьбой сократить период, а не сохраняет неполный снимок.

Ручной ввод продаж и редактирование выплат отключены. Старые ручные записи сохранены в базе и в резервных копиях; при их наличии доступен сворачиваемый раздел истории только для чтения.


### Общие ключи, остатки и шаблоны карточек

«API и доступы» — общий раздел ключей WB/Ozon, проверки прав и загрузки справочников. Кнопки настройки карточек, заказов и остатков ведут сюда. Хранилище ключей прежнее, повторный ввод сохранённых ключей не требуется; ключи по-прежнему исключены из JSON/ZIP.

«Остатки WB / Ozon» показывает товар и артикул, склад, доступное количество, резерв и путь к покупателю/возврат. Фильтры схемы, склада, поиска; 50 строк на странице. Отсутствующие показатели отображаются прочерком. Обновление ручное, ошибки не заменяют предыдущий снимок, дата снимка видна. Снимки входят в резервные копии.

- WB FBS: карточки (`Контент`), список складов и чтение остатков (`Маркетплейс`), остатки по chrtID на каждом складе.
- WB FBW: `GET /api/v1/supplier/stocks`, хост Statistics, доступ «Статистика». Отчёт WB может обновляться с задержкой. Для больших отчётов от 60 000 строк полнота не считается подтверждённой.
- Ozon FBS: `POST /v2/product/info/stocks-by-warehouse/fbs`, роль Stocks; современная пагинация cursor/has_next. [Справка Ozon](https://docs.ozon.ru/api/seller/#operation/ProductAPI_GetProductInfoStocksByWarehouseFbsV2).
- Ozon FBO: `POST /v1/analytics/stocks` по SKU, проверьте роль Report (отчёты) и наличие метода в ответе `/v1/roles`; отдельная роль Analytics не требуется. [Справка Ozon](https://docs.ozon.ru/api/seller/#operation/AnalyticsAPI_AnalyticsStocks).
- Для чтения всех товаров Ozon используется Product. Отчёты об остатках не отправляют изменений на площадку.

В карточках блок «Шаблоны карточек по категориям»: сохранить текущую карточку, обновить выбранный шаблон целиком, удалить шаблон, создать новый локальный товар из шаблона. Шаблон привязан к площадке, категории и типу; обновление из другой категории запрещено. Сохраняются значения полей, справочная схема характеристик, описание, упаковка и публичные ссылки на фотографии. Файлы исходников другого товара не присваиваются новому. При создании очищаются ID карточки и размеров, исходный артикул и штрихкоды. Эти поля заполняются для нового товара отдельно; публикация требует отдельного действия в редакторе.

Пустые характеристики и основные пустые поля шаблона скрыты по умолчанию. Артикул, название и блок штрихкодов доступны, чтобы задать данные нового товара. «Показать все поля, включая пустые» возвращает скрытые поля, без удаления значений и изменения проверки обязательных характеристик. Шаблоны карточек хранятся отдельно от шаблонов себестоимости и включены в JSON/ZIP.

В чтении WB FBS исправлен курсор `next`: значение читается из JSON как десятичная строка и передаётся в GET без округления 64-битных чисел JavaScript. Ошибки 403 показывают редактированный ответ API, а сообщение о сохранении предыдущих данных появляется только при наличии снимка.

Таблица остатков разделена на Wildberries и Ozon. Внутри каждой площадки строки сгруппированы по `productGroup` локального товара, найденного по артикулу; неизвестные товары идут в «Без группы». Артикул — главное поле строки; название, цвет и штрихкоды отображаются ниже. Количества выровнены вправо, заголовки закреплены при прокрутке; ноль и неизвестный остаток визуально различаются. Сортировка и оформление не меняют значения снимков.

Заказы оформлены одной общей таблицей Wildberries и Ozon, внутри которой — разделители площадок и группы по статусам, с количеством заказов и позиций на текущей странице. Артикул вынесен первым. Исходные коды статусов доступны в раскрываемых подробностях строки. Группы сортируются по этапу: сборка, отгрузка, доставка, получение, выкуп, возврат и отмена; неизвестные статусы сохраняются.

В каждом из разделов «Продажи» и «Остатки WB / Ozon» используется одна общая таблица, одна шапка колонок и одна область прокрутки для обеих площадок. Группы товаров/статусов и подписи площадок сохранены. Текущий раздел бокового меню выделен светлым фоном и маркером, отмечен `aria-current="page"`.

В остатках фильтры и кнопки объединены в одну адаптивную панель. Даты обновления четырёх схем и итог отображаются компактно под элементами управления; пустое сообщение состояния не занимает место. В навигации «Остатки филамента» находятся сразу после остатков товаров.

### Нормы остатков и допечатка
В себестоимости каждого товара блок «Нормы остатков на маркетплейсах» хранит отдельные минимальный и нормальный остатки WB/Ozon. Оба значения — целые неотрицательные числа, нормальный должен быть больше минимального. Пустое значение отключает расчёт для площадки. Нормы принадлежат товару, входят в JSON/полный ZIP и сохраняются при применении шаблона расчёта.

Справа от остатков таблица «Надо допечатать» сравнивает сумму доступных остатков артикула на всех загруженных складах/схемах площадки с минимумом. При `остаток <= минимум` количество равно `норма - остаток`. Резерв и товары в пути не прибавляются. Фильтры/пагинация основной таблицы не меняют план. Отсутствующие или неизвестные остатки не считаются нулём и вынесены в «Не хватает данных». Рекомендации пересчитываются при открытии раздела и обновлении данных; фоновых запросов и изменений остатков площадки нет.

В основной таблице остатков кнопка «Показать нормы» раскрывает колонки минимального и нормального остатка. Правки сохраняются локально для артикула и площадки, синхронизируются между строками его складов и сразу пересчитывают правую сводку. Если артикул есть только в снимке площадки, первая правка создаёт локальный товар с этим артикулом. Кнопка «Скрыть нормы» убирает колонки, сохраняя значения.

Справа «Остатки по артикулам» показывает все артикулы из товаров и снимков, остатки WB/Ozon, общую сумму и сумму допечатки по двум площадкам. Фильтр «Все / Нужно допечатать» независим от основной таблицы. Частично известные суммы отмечены «+ ?», полностью неизвестные — прочерком.

При раскрытых нормах заголовки WB и Ozon содержат кнопку «Скопировать нормы из …». Она переносит обе нормы всех локальных товаров с корректно заполненной парой, заменяя нормы площадки назначения. Пустые/некорректные исходные пары пропускаются. Фильтры и страница таблицы не ограничивают копирование; ключи API и реальные остатки не изменяются.

Главные фото в таблицах остатков и заказов загружаются при обновлении данных: WB — из Content API, Ozon — из информации о товаре (сначала `primary_image`). Ссылки сохраняются со снимками и входят в резервную копию; также используются изображения сохранённых карточек. Отсутствие прав на фото не отменяет загрузку остатков/заказов. Недоступные изображения заменяются заглушкой, миниатюры загружаются лениво без заголовков API и без Referer.

Основная таблица остатков: одна строка на артикул, рядом колонки WB и Ozon с суммой доступных остатков выбранных складов/схем. Подробности склада, резерва, движения и штрихкоды раскрываются внутри соответствующей ячейки. При показе норм доступны четыре отдельные колонки (минимум/норма WB и Ozon). Пагинация по 50 артикулам не разделяет площадки или склады одного артикула между страницами.

### Модель конкретного товара
В «Файлы товара → Модель для печати» выберите или загрузите модель конкретного артикула и цвета. Замена модели не меняет другие варианты. При обновлении приложения старые групповые модели один раз преобразуются в независимые ссылки товаров; файлы не теряются и не дублируются. Новый цветовой вариант получает собственную модель и не наследует её автоматически. Файл можно скачать из карточки, из сводки остатков или из очереди печати. Полный ZIP сохраняет файлы и ссылки; старые ссылки между товарами корректно восстанавливаются.

### Добавление новых деталей на склады FBS
Обновите остатки, затем раскройте «Склады и пополнение» в колонке WB или Ozon. У нужного склада поле **«Новых деталей, шт.»** означает прибавление, а не замену остатка: было 3, введено 5, ожидается 8. Кнопка «Добавить на склад» перед подтверждением читает свежий остаток и повторно проверяет его перед записью. После отправки выполняется чтение результата. Для складов площадок WB FBW/Ozon FBO такие поля не показываются.

API задаёт абсолютное число: WB `PUT /api/v3/stocks/{warehouseId}` с `chrtId`/`amount`; Ozon `POST /v2/products/stocks` с `offer_id`/`warehouse_id`/`stock`. Для Ozon используется `free_stock`, резерв не прибавляется повторно. Нужны права записи WB «Маркетплейс» и Ozon Product. [Изменения WB](https://dev.wildberries.ru/en/release-notes?id=347), [справка Ozon](https://dev.ozon.ru/start/257-FAQ-spravochnik-oshibok-i-sposoby-ikh-resheniia).

Журнал `stockAdditions` сохраняется в базе и полном ZIP до запроса записи. Сетевая ошибка или неподтверждённая обработка блокирует повторное прибавление на тот же склад/размер до проверки. «Проверить результат» повторяет только чтение. «Проверил в кабинете» снимает блокировку после явного подтверждения пользователя; повторный запрос после этого считается новым пополнением. Автоматического повтора записи нет. API не предоставляет атомарную операцию `+N`: заказ между последней проверкой и записью всё ещё возможен; успешный HTTP-ответ не выдаётся за подтверждённый итоговый остаток.

### Отсутствующие остатки
Артикулы без полученного числового остатка на обеих площадках не выводятся в основной таблице и сводке справа. Реальный нулевой остаток остаётся видимым. Локальные товары и файлы сохраняются; переносить их в архив не требуется. «Мои товары» находятся в отдельной колонке рядом с меню в разделах себестоимости и карточек.

### Этикетки при допечатке
В себестоимости, в «Файлы товара» рядом с моделью, загрузите PDF этикетки конкретного артикула (до 2 МБ). Существующие этикетки используются автоматически. В правой таблице «Остатки по артикулам» нажмите «Печать этикетки»: окно покажет количество для допечатки и откроет PDF для принтера. Число копий выберите в диалоге печати браузера. В остатках загрузки/замены нет; если PDF отсутствует, кнопка «Нет этикетки» недоступна. PDF входит в резервную копию, не копируется к новому цветовому варианту и не заменяется шаблоном.

### Загрузка остатков WB FBW и лимиты Ozon
WB FBW использует новый POST `/api/analytics/v1/stocks-report/wb-warehouses` на `seller-analytics-api.wildberries.ru`, с токеном «Аналитика». Артикул продавца и штрихкод сопоставляются с карточкой по nmID/размеру. Страницы отчёта запрашиваются с интервалом 20 секунд; старый `/api/v1/supplier/stocks` больше не используется. Для Ozon FBO предусмотрена пауза перед запросом аналитики и до трёх повторов чтения при HTTP 429 с увеличением ожидания и учётом Retry-After (до минуты). Ошибка не заменяет сохранённый снимок. Повторы записи остатков или карточек не добавляются. [Документация WB](https://dev.wildberries.ru/docs/openapi/analytics#tag/Istoriya-ostatkov/operation/postV1StocksReportWbWarehouses).

### Очередь печати
Раздел «Склад → Очередь печати» хранит задания на конкретный вариант, цвет, материал и количество. Добавляйте вручную или из остатков — кнопкой «В очередь печати» рядом с рассчитанной допечаткой в таблице WB/Ozon и в сводке справа. Количество подставляется из расчёта минимум/норма; окно показывает уже ожидающее печати количество и позволяет его проверить.

В задании доступны модель, этикетка и переход к товару. Введите «Напечатано сейчас»: частичная партия уменьшит остаток, полная завершит задание и перенесёт его в компактный раскрывающийся архив внизу. Отмена задания с уже учтёнными партиями также сохраняет его в архиве. В окне партии можно напечатать этикетки и сразу выбрать склад WB/Ozon FBS для добавления именно этой партии к свежему остатку. Подтверждение и проверка результата используют существующий журнал `stockAdditions`. Партия связывается с запросом до отправки; при неопределённом результате повтор блокируется, доступна проверка. Незавершённое чужое пополнение того же склада не присваивается новой партии. Для WB FBW и Ozon FBO пополнение требует поставки через кабинет.

Отложенные партии доступны в списке «Партии» активного задания и архива. Очередь, партии и журнал входят в JSON и полный ZIP. Кнопки «Назад»/«Вперёд» в приложении возвращают между посещёнными разделами и выбранными товарами в рамках текущего сеанса.

В себестоимости кнопка «Удалить этот вариант» удаляет только выбранный локальный товар, сохраняя соседей по группе. Перед удалением создаётся предыдущая копия базы для восстановления через «Бэкап». Старые модели, используемые другими товарами, передаются оставшемуся владельцу. Если удалён последний товар, открывается пустая карточка. Удаление не отправляется на маркетплейс.

### Тексты рич-контента Ozon
Откройте существующий вариант в «Карточки WB / Ozon → Ozon». В блоке «Тексты рич-контента Ozon» загрузите TXT с разделами `БЛОК 1 — Заголовок` и текстом ниже, вставьте блоки вручную или подставьте только тексты другой сохранённой карточки. Список файлов после строки «ПОРЯДОК» и инструкции WB из TXT не включаются. Новые блоки формируются как текстовые виджеты `raTextBlock` формата 0.3 — изображения и внешнее хранилище не нужны. Изображения добавляются позже в кабинете Ozon.

Режим замены текстов в существующих блоках сохраняет изображения и оформление; количество текстовых блоков должно совпадать. «Подставить в черновик» сохраняет только локальные сведения. «Отправить только рич-контент» перечитывает актуальный рич и отправляет один атрибут 11254 выбранного offer_id через `/v1/product/attributes/update`, без поля фотографий и прочих характеристик. Для записи нужна роль Product. Задача/неопределённый результат сохраняются; автоматических повторов нет. «Проверить применение» проверяет задачу и перечитывает рич выбранного артикула, сопоставляя тексты. Принятый запрос сам по себе не считается подтверждением.

Старый отдельный редактор фотографий WB/Ozon и блоки загрузки исходников убраны из интерфейса. Ранее сохранённые файлы остаются в резервной копии и ZIP товара. Схема текстовых блоков проверена по [официальной схеме Ozon](https://st.ozone.ru/s3/artifact/schema.json).

### Цены WB / Ozon

Раздел «Маркетплейс → Цены WB / Ozon» загружает полный список цен напрямую с площадок, независимо от локальных товаров и остатков. Артикул — первый столбец, WB и Ozon — соседние столбцы. Снимки цен сохраняются на устройстве и входят в резервные копии. При ошибке чтения прежний снимок остаётся.

WB: начальная цена и скидка продавца; Ozon: цена продажи, зачёркнутая и минимальная цена. Отправка — отдельно для каждого артикула и площадки после проверки актуальной цены и подтверждения. Кнопка «Проверить / получить» подтверждает применение чтением цены. Приём задачи WB ещё не означает применение. Итоговые скидки покупателя и акции площадок не редактируются в этой таблице. Товары WB с отдельными ценами по размерам следует менять в кабинете WB. Для записи нужны WB «Цены и скидки» и Ozon Product; ключи берутся из общего раздела «API и доступы».

Новые действующие карточки без переданного остатка теперь показываются в остатках с прочерком и подписью «Остаток не задан площадкой». Если действующая карточка есть на площадке, но её остаток не задан, для расчёта допечатки принимается 0. Ошибка чтения или отсутствие сведений о карточке по-прежнему означают неизвестный остаток. Для этого нужно обновить остатки: старые снимки не содержат признака действующей карточки. Архивные карточки Ozon исключаются из нового чтения списка товаров.

Первое пополнение незаданного остатка: в «Склады и пополнение» можно ввести новые детали; если ID склада ещё не получен, кнопка «Выбрать склад и добавить детали» загружает склады продавца и позволяет выбрать нужный. Ozon использует актуальный `/v2/warehouse/list`. Для первого пополнения пустой успешный ответ об остатке принимается за 0 только после проверки действующей карточки (и размера WB). Ошибки API, архивная или отсутствующая карточка, некорректный ответ не превращаются в ноль. Перед отправкой остаток читается повторно, пополнение записывается в журнал; неподтверждённое добавление повторно не отправляется.

В таблице цен показывается главное фото WB/Ozon; прикреплённое в себестоимости изображение имеет приоритет. Кнопка «Обновить цены» догружает фото со сведениями о карточках. Для WB блок «Итог после скидки продавца» пересчитывается при каждом изменении начальной цены и скидки, без отправки запроса. Цена на площадке из последней загрузки подписана отдельно; пересчёт не изменяет опубликованную цену до нажатия «Отправить цену».

В «Остатках филамента» кнопка «Настроить закупку» раскрывает два поля для каждого типа пластика и кода цвета: минимальный остаток мотков и фиксированное количество мотков для закупки при достижении этого минимума. Если остаток меньше или равен минимуму, всегда видимый отчёт «Нужно докупить» показывает заданное количество. Поиск по цветам не ограничивает отчёт. Пустое поле отключает правило; поступление мотков автоматически убирает позицию из отчёта после превышения минимума. Нормы входят в базу и полный ZIP-бэкап.
