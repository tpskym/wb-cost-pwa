# Правила проекта «Мастерская»

## Кнопки и элементы выбора

Эти требования закреплены по просьбе пользователя. Соблюдать при создании и изменении интерфейса, чтобы не возвращаться к исправлению мелких стандартных элементов.

- Обычные кнопки и одиночные поля выбора должны выглядеть как полноценные элементы управления: высота не менее 44 CSS px, текст от 14 px, внутренние отступы примерно 10–14 px, скругление 8–12 px. На телефоне сохранять удобную область нажатия.
- Для одиночного `select` использовать общий класс `ui-select` из `style.css`. Он задаёт `appearance: none`, `-webkit-appearance: none`, явную высоту, отступ справа и заметную стрелку. Нельзя оставлять маленький системный select, который в Safari игнорирует отступы и выглядит узкой полоской. Не применять этот класс к `multiple` и спискам с `size`.
- Между соседними кнопками в группе оставлять `gap` 10–12 px (не склеивать их и не добавлять случайные внешние отступы каждой кнопке). Между блоком полей и действиями давать 20–24 px, внутри карточек 18–24 px. Счётчики «− число +» сохраняют собственные компактные отступы; подпись всегда над счётчиком с зазором 10–12 px, а не в одной строке вплотную. Между счётчиком и следующей группой действий оставлять не менее 16 px.
- В строке формы выравнивать высоту выбора, поиска и соседних полей. Подпись располагать над элементом с зазором. Текст и стрелка не должны накладываться друг на друга.
- При выборе одного из небольшого числа типов допустимы крупные кнопки с иконками. Выбранный вариант явно отмечать цветом, рамкой и галочкой; обеспечивать доступное состояние (`aria-pressed` или корректную радио-группу).
- Для разных действий использовать понятные подписи и различимые иконки. Основное действие выделять, второстепенные оставлять спокойными. Учитывать состояния наведения, клавиатурного фокуса и недоступности; не делать текст почти невидимым.
- Количество изделий, деталей, мотков, единиц покупки и нормы остатков изменять только кнопками «−» и «+» через общий `data-buttons-only` счётчик. По умолчанию ручной ввод количества запрещён. Исключение по уточнению пользователя: в затратах рядом со счётчиком есть отдельная кнопка «Ввести вручную» для больших партий (например, 1000 коробок). Она открывает явный ручной ввод с применением или отменой; остальные счётчики остаются только кнопочными. Цены, суммы, проценты, размеры и другие параметры не считать количеством.
- После успешного добавления в очередь или подтверждённого пополнения из очереди показывать крупное явное подтверждение: что выполнено, какой товар и сколько, кнопку «Готово — закрыть». Мелкой строки или краткого toast недостаточно. Не показывать успех при ошибке или неизвестном результате API.
- Действие открытия/передачи модели в слайсер называть «Печать модели». На всех таких кнопках показывать объёмный значок 3D; на всех кнопках печати этикеток — принтер. Использовать общие `print-action-controls.js` и классы `print-action`, сохраняя единое цветное оформление во всех разделах.
- Если ручной ввод запрещён, значение показывать как число/`output` рядом с кнопками, а не как редактируемое текстовое поле.
- Не исправлять одинаковую проблему отдельными разрозненными стилями: использовать общий класс и расширять его при необходимости. При правке существующего элемента подключать общее оформление без изменения его поведения.
- Перед завершением визуально проверять изменённую форму на широком экране и при ширине телефона 390 px: реальная высота элемента, видимая стрелка, читаемость, фокус, отсутствие горизонтального переполнения. Для Safari учитывать особенности нативных элементов; не заявлять о проверке в Safari без фактической проверки.

- Подтверждения действий показывать через общий асинхронный `confirmAction` с содержательным названием действия вместо системного `confirm` и кнопки «OK». До подтверждения данные не менять.

## Объём изменений и проверки

Сохранять рабочую логику, данные и выбранные значения при изменении оформления. Для небольших визуальных правок достаточно подходящих существующих проверок и осмотра интерфейса; не писать тесты, которые лишь повторяют CSS. При изменении поведения проверять пользовательский сценарий.

- Общие счётчики «− число +»: высота всей строки и кнопок 44 px через `--stepper-size`, символы 22 px, значение 18 px. Не увеличивать счётчик внешними внутренними отступами; соседние поля той же высоты. Размеры задавать в общем блоке стилей, а не отдельно для разделов.
